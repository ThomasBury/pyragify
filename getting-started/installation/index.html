    Installation¶

    This guide will help you install Pyragify on your system.

    Prerequisites¶

    • Python: Version 3.12 only (>=3.12,<3.13)
    • Operating System: Linux, macOS, or Windows

    Installation Methods¶

    Method 1: Using uv (Recommended)¶

    uv is a fast Python package manager that handles virtual environments automatically.

    # Install uv if you don't have it
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install Pyragify
uv pip install pyragify

    Method 2: Using pip¶

    If you prefer using pip, you can install Pyragify from PyPI:

    # Install Pyragify
pip install pyragify

# Optional: Create a virtual environment first
python -m venv pyragify-env
source pyragify-env/bin/activate  # On Windows: pyragify-env\Scripts\activate
pip install pyragify

    Method 3: From Source¶

    If you want to install from source (for development or the latest features):

    # Clone the repository
git clone https://github.com/ThomasBury/pyragify.git
cd pyragify

# Install with uv (recommended)
uv sync --locked --group dev --group docs

# Or with pip
pip install -e .

    Agent skills¶

    Pyragify 0.5.0 bundles two self-contained skills: pyragify-export covers source-only exports and manifest inspection; pyragify-graph covers experimental graph export and queries with source checks. Versions before 0.5.0 do not contain them. Once 0.5.0 or later is available on your package index, install from a consuming project using Python 3.12:

    uv add --dev pyragify
uvx library-skills install --skill pyragify-export --skill pyragify-graph
uvx library-skills scan --json

    PyPI publication is separate from the GitHub release. Until the package is on your index, use the 0.5.0 release wheel URL so other developers and CI can sync the same dependency:

    uv add --dev https://github.com/ThomasBury/pyragify/releases/download/0.5.0/pyragify-0.5.0-py3-none-any.whl

    uv records that wheel URL under [tool.uv.sources], so normal upgrades keep using the same wheel. After 0.5.0 or later is available on your package index, remove only the pyragify entry from [tool.uv.sources] in pyproject.toml, then run uv lock --upgrade-package pyragify and uv sync --python 3.12 to resolve and install from the index.

    Both commands assume the consuming project's declared requires-python is >=3.12,<3.13. uv resolves against that entire range, not just the interpreter currently running. If your project supports other Python versions, add --marker 'python_version == "3.12"' to either uv add command to limit this development dependency to Python 3.12. The marker does not select an interpreter. Before adding the dependency, select Python 3.12 for the project environment:

    uv python pin 3.12
uv sync --python 3.12

    Then run the chosen uv add command with the marker. Use uv run pyragify for exports; uvx library-skills scans the project's now-synced .venv. See uv's resolution rules.

    Library Skills discovers skills inside installed library packages. It scans the project's environment, so a global installation or an isolated uvx pyragify CLI alone does not support this workflow. Run discovery and installation from the project root with its environment synced.

    The default targets are .agents/skills/pyragify-export and .agents/skills/pyragify-graph. The official CLI options include --claude to install additional targets under .claude/skills and --copy to create ordinary directories where symlinks are unavailable:

    uvx library-skills install --skill pyragify-export --skill pyragify-graph --claude
# Alternative for environments without symlinks:
uvx library-skills install --skill pyragify-export --skill pyragify-graph --copy

    Symlinked skills follow the installed package version. Copied skills require refreshing after upgrades: remove the old copied skill directories and reinstall with --copy, preserving any local edits separately.

    To use a source checkout containing these skills:

    git clone https://github.com/ThomasBury/pyragify.git
cd pyragify
uv sync --locked
uvx library-skills scan --all --json
uvx library-skills install --skill pyragify-export --skill pyragify-graph

    --all includes the checkout package itself, which is not one of its own declared dependencies. In a consuming project, the default scan includes Pyragify because it is a declared dependency.

    The local packaging check uses Library Skills 0.0.19 against isolated wheel, editable, and source-distribution installations:

    uv run --locked python scripts/check_skill_packaging.py

    Installation from PyPI remains unverified until PyPI publication.

    CLI verification¶

    After installation, verify that Pyragify is working:

    # View help
pyragify --help

    You should see output similar to:

    Usage: pyragify [OPTIONS] COMMAND [ARGS]...

Export complete repository source as Markdown with a provenance manifest.

Options:
  --help  Show this message and exit.

Commands:
  process-repo  Process a repository and output its content to text files...
  query-graph   Query the knowledge graph for context and relationships.

    Parser Dependencies¶

    Official Tree-sitter Python bindings and eight individual grammar packages (JavaScript, TypeScript, Java, C, C++, Go, HTML, and CSS) are required dependencies, installed with Pyragify at pinned versions. Do not upgrade them independently. Python analysis continues to use the standard-library ast module.

    For a source checkout containing pyproject.toml and uv.lock, install the locked dependencies from the checkout root:

    uv sync --locked

    This command is for repository development, not for a standalone pip installation.

    Development Dependencies¶

    From the root of a source checkout:

    uv sync --locked --group dev --group docs

    Troubleshooting¶

    Common Installation Issues¶

    Permission Errors¶

    If you get permission errors during installation:

    # Use --user flag with pip
pip install --user pyragify

# Or use uv which handles this automatically
uv pip install pyragify

    Python Version Issues¶

    Ensure you're using Python 3.12:

    python --version
# Should show Python 3.12.x

    Virtual Environment Issues¶

    If you're having trouble with virtual environments:

    # Create and activate a new environment
python -m venv pyragify-env
source pyragify-env/bin/activate  # Linux/macOS
# pyragify-env\Scripts\activate   # Windows

# Install in the activated environment
pip install pyragify

    Testing the Installation¶

    Create a simple test to verify everything is working:

    # Create a test directory
mkdir test-repo
cd test-repo

# Create a simple Python file
echo 'def hello_world():
    """A simple function."""
    print("Hello, World!")
    return "success"' > test.py

# Create a basic config
echo 'repo_path: .
output_dir: ./output
max_words: 50000' > config.yaml

# Test Pyragify
pyragify process-repo --config-file config.yaml --verbose

    If successful, you should see output indicating the repository was processed.
